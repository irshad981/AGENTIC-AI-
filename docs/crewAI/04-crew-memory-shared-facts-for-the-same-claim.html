Let the Crew Remember

The same Suraksha chat. The two workers still run in order. This time the team keeps short facts from earlier questions about the same file.

How to follow this page.
  • You already have two agents, two tasks, the database lookups, and the chat.
  • Do the steps in order.
  • The file you change is crew.jsonc.
  • In Step 1 you add a few lines. In Step 2 you replace each task description with the full prompt on this page.
  • Copy each prompt as it is written.
  • Leave the agents and the chat as they are.
  • After each step, check what you should see before you continue.
  • New words are explained in parentheses the first time they appear.

The story, in plain words

  • You are still the claims officer (the human at the keyboard).
  • The coverage officer agent opens the database and writes the coverage opinion (a first reading of whether the contract seems to cover the accident).
  • The examiner brief agent then writes the brief (the short note for the meeting).
  • Neither note pays anyone. A senior examiner (a more senior human, not in this chat) still decides the money.
  • Each question still starts from the accident story and the database.
  • If you tell the agent something new, the next question does not know you said it.
  • The chat window also forgets the bubbles (the messages on the page) when you switch claims.
  • A person at a claims desk does not work like that. If the surveyor (the person who looks at the damaged car and reports what the photos show) phones and says the photos show rear damage only, the next person who opens that same file should still know.
  • CrewAI calls that store memory (short facts saved after an answer, then searched before the next answer).
  • With memory on, the crew saves short facts after each task.
  • Before the next task, it looks those facts up and hands the matching ones to the agent.
  • Both agents share this one memory. Neither agent file has a private memory of its own.
  • Memory is not the database, and it is not the chat bubbles.
Memory is not the database.
  • Policy Record and Earlier Claims are still the records.
  • A remembered fact is something said in an earlier question.
  • The agent must say it came from that earlier question.
  • It must not pretend the fact was in the policy table.
A fact about one claim must stay on that claim.
  • Both agents share the same memory.
  • The memory is still there after you switch files in the sidebar.
  • A note about CLM-20481 must not be used when the question is about CLM-10021 or CLM-10044.
  • The task text below says so.

How a matching fact is chosen

  • Each stored sentence gets one composite score.
  • CrewAI hands back the sentences with the highest scores.
  • The score is a weighted sum of three numbers, each from 0 to 1.
  • The names below are the names in CrewAI's compute_composite_score.
composite = semantic_weight * semantic_score
          + recency_weight * decay
          + importance_weight * importance

decay = 0.5 ** (age_days / recency_half_life_days)
  • With the defaults, that is 0.5 * semantic_score + 0.3 * decay + 0.2 * importance.
  • The three weights add up to 1, so composite stays between 0 and 1.
  • ** means "raised to the power of".
PieceName in the formulaOn the surveyor sentence
Meaningsemantic_score, multiplied by semantic_weight 0.5
  • How close the question is to the stored sentence.
  • "What did the surveyor say about the photos?" can match "the photos show rear damage only" even when the words differ.
  • This is the largest share.
Freshnessdecay, multiplied by recency_weight 0.3
  • A sentence saved just now has decay 1.0. An older sentence has a smaller decay.
  • recency_weight is the share of the score. It is not the half-life.
Importanceimportance, multiplied by importance_weight 0.2
  • A number from 0 to 1 chosen when the sentence was saved, and stored on the record.
  • It stays put as the days pass.
  • recency_half_life_days is used only inside decay.
  • It is the number of days until freshness falls by half. The default is 30.
  • CrewAI counts age_days from the sentence's created_at (seconds since it was saved, divided by 86400).
  • It then divides that age by recency_half_life_days and uses the result as the exponent:
decay = 0.5 ** (age_days / recency_half_life_days)
  • A larger recency_half_life_days makes decay fall more slowly.
  • With the default of 30:
age_daysExponentdecay
00 / 30 = 00.5 ** 0 = 1.0
3030 / 30 = 10.5 ** 1 = 0.5
6060 / 30 = 20.5 ** 2 = 0.25
9090 / 30 = 30.5 ** 3 = 0.125

Take a surveyor sentence with semantic_score 0.8 and importance 0.5:

  • Saved today, decay is 1.0. composite = 0.5*0.8 + 0.3*1.0 + 0.2*0.5 = 0.80.
  • 30 days later, decay is 0.5. composite = 0.40 + 0.15 + 0.10 = 0.65.
  • 60 days later, decay is 0.25. composite = 0.40 + 0.075 + 0.10 = 0.575.
  • Meaning still supplies 0.40 of that score.
  • Freshness adds 0.30 today and 0.075 after 60 days.
  • A phone call from today outranks a similar note from last quarter when the wording is equally close.
  • There is a faster search, depth="shallow", which compares vectors and applies the score above, with no extra model call.
  • "memory": true uses deep.
  • When the query is a long task description, the model first picks likely folders and may search a second time when the first pass looks unsure.
  • This desk does not do that. The prompt names the short question, and that is the search that runs.
